# superagent v0.2.2 — fix contract

Fixes for the second adversarial review of v0.2.1. Branch `fix/v0.2.2`; the Lead owns git.
Do not change an interface here without the Lead's agreement.

## A. retarget must be usable with the replacement the skill recommends (Lead)

`retarget <T> --depends-on <ids|none>` currently rejects a dependency in a later wave
("T9 is in wave 2, later than T2's wave 1"), but the skill's handback flow always puts the
replacement in a later wave. Change: when a new dependency's wave is later than the ticket's wave,
`retarget` moves the ticket to the highest dependency wave (like `git` moving a ref), records the old
and new waves in the `ticket_retargeted` event, and prints them. Self/unknown/duplicate/cycle/failed
dependency rules stay. Update the SKILL wording if needed. Tests: the exact scenario (T1 and T2 in
wave 1, T2 depends on T1, T1 fails, handback T9 in wave 2, `retarget T2 --depends-on T9` succeeds and
T2 is wave 2), plus a whole-flow test that T2 then launches after T9 merges.

## B. merge-continue must record every commit the merge produced (audit-dev)

If a merge is committed with conflict markers, `merge-continue` refuses and says "commit the fix";
the fix commit is recorded but the merge commit itself is not, so `audit` later calls the merge commit
rogue and tells the user to delete it. Change `finishMerge` in `lib/commands/merge.mjs` to record, in
the `merged` event, every first-parent commit added since the previous recorded merge (or
`run.base_sha` for the first): keep `sha` (HEAD) and add `shas: string[]`. `audit` in
`lib/commands/health.mjs` must accept the union of every `merged` event's `sha` and `shas`.
Regression test: conflict → commit the merge with markers → `merge-continue` refuses → remove
markers and commit → `merge-continue` succeeds → `audit` passes and does not call the merge commit
rogue. A rogue commit made directly in the main checkout must still fail.

## C. Review coverage matching must be forgiving, and the run must recover (Lead)

Exact-string coverage is too strict: "Alpha works." vs "alpha works" stops `finish`. Normalize
before comparing: trim, collapse whitespace, lowercase, and strip trailing sentence punctuation
(`. , ; : ! ?`). Keep both-lists and missing-item errors. Update the SKILL: when `superagent review`
rejects a review with coverage (or any validation) errors, send the reviewer the exact error once and
have it correct the JSON; record the corrected review; if it fails a second time, tell the user the
review is invalid. Tests: case/punctuation variants accepted; a genuinely missing item still rejected;
SKILL mentions the single relaunch.

## D. The eval acceptance must be harness-owned (evals-dev)

Running each arm's own tests is not independent (a repo with `"test": "true"` passes). Make the
bookmarks fixture an explicit Node HTTP contract and give the harness its own acceptance test:
- Update the fixture idea (and the arm prompts) to require: a Node.js web app started by
  `npm start` (or `node server.js`); listens on `process.env.PORT`; stores bookmarks durably
  (SQLite or JSON file); `POST /api/bookmarks` with `{url, title}` and `GET /api/bookmarks` returning
  all bookmarks newest first. Tests of its own are welcome but not the acceptance criterion.
- `evals/accept.mjs <repo>` becomes the harness-owned test: install runtime deps if needed, start the
  app on a free port with a temp database path, wait for it, POST two bookmarks, GET the list, assert
  both are present with the newest first and the expected fields, then stop it. Fail with a useful
  message (did not start, wrong status, wrong order, missing field, timed out); exit 0/1.
- Run it after every arm in live mode and keep recording the result. Update `evals/README.md`
  (accuracy is now an independent contract test; app must follow the contract) and
  `test/evals.test.mjs` (a tiny fixture Node server that passes and one that fails/does not start).
- Do not run a live eval.

## E. Eval environment must not silently load the caller's global config (evals-dev)

Live runs currently default to the caller's real config, so global plugins, hooks and CLAUDE.md load
into every arm and distort the comparison. Change the default: isolated throwaway `CLAUDE_CONFIG_DIR`
(the measurement is reproducible), and require `ANTHROPIC_API_KEY` for live runs; on a missing key,
stop with a message that names the key or `--user-config`. `--user-config` explicitly opts into the
caller's config and prints one clear warning that global plugins/hooks/CLAUDE.md apply; keep
`--isolated-config` as an accepted alias for the default. Update dry-run output, README and tests.
